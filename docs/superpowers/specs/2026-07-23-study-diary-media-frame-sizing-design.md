# Study Diary 媒体相框尺寸设计

## 目标

让横图和横屏视频充分利用日记右页宽度，不再被统一的 `330px`
Polaroid 外框限制；同时保持竖图、方图和移动端版式协调。

## 当前问题

媒体区域已经能够识别横向、方形和竖向比例，但外层
`.diary-polaroid` 始终固定为 `330px`。扣除相框左右内边距后，横屏视频
的有效画面宽度约为 `302px`，因此即使使用 `16:9`，视觉上仍显得偏小。

## 设计

- 单横向图片或视频：Polaroid 在桌面端使用 `380px`，并受右页
  `max-width: 100%` 约束。
- 单方形媒体：Polaroid 使用 `350px`。
- 单竖向或尚未解析比例的媒体：继续使用 `330px`。
- 多图片画廊保持现有 `330px`，避免拼贴页面突然变宽。
- 平板端横向媒体允许使用页面可用宽度，但不突破右页；方形、竖向和
  画廊沿用较紧凑的现有尺寸。
- 移动端所有相框继续受视口限制；横向媒体可以比当前 `270px` 更宽，
  但必须保留页面边距，竖向媒体继续为 `270px`。

## 实现方式

比例解析结果除应用在 `.diary-page__media` 上，还会向所属
`.diary-polaroid` 添加对应方向类：

- `.diary-polaroid--landscape`
- `.diary-polaroid--square`
- `.diary-polaroid--portrait`
- `.diary-polaroid--unknown`
- `.diary-polaroid--gallery`

静态页面 hydration 时同步外框类；翻页临时页面直接从缓存布局生成相同
外框类，不注册新的媒体加载监听器。这样翻页时外框宽度不会跳回默认值。

## 视觉与交互约束

- 图片和视频继续使用 `object-fit: contain`，不能裁切。
- 视频原生 controls 保持不变。
- 外框宽度变化使用现有短过渡；减少动态效果时不做过渡。
- 不改变书本宽度、翻页几何、上传、Supabase 数据结构或媒体比例算法。

## 测试与验收

- 自动化测试验证横向、方形、竖向、未知和多图生成正确的外框类。
- 验证 hydration 会更新外框方向类。
- 验证翻页 current、target 和 slices 从缓存继承外框类。
- 浏览器检查横屏视频外框明显宽于竖图，并保持在右页内部。
- 检查桌面端、移动端以及双向翻页时没有溢出或宽度跳变。

## 非目标

- 不修改中文文件名导致的 Supabase `InvalidKey` 问题；该问题属于独立的
  上传路径修复。
- 不增加手动相框大小选择。
